# Обучаемые допустимые дефекты: краткое API

Дополнение позволяет оператору открыть результат `БРАК`, выбрать конкретный
дефект и сохранить его как допустимую норму. Уже отправленный на конвейер
вердикт не меняется. Совпавшие фрагменты исключаются только из следующих
инспекций.

Базовый адрес при локальном запуске: `http://127.0.0.1:8000`.

## Изменения ответа инспекции

Эти поля добавлены в ответы существующих `POST /inspect`, `POST /inspect-shm`
и `POST /inspect-shm-visuals`:

| Поле | Тип | Значение |
|---|---|---|
| `inspection_id` | `string \| null` | ID операторского разбора. Заполняется для итогового `БРАК`, если есть значимые дефекты. |
| `learned_normal_matches_count` | `integer` | Количество найденных компонентов, совпавших с допустимой нормой. |
| `learned_normal_adjustment` | `number` | Насколько уменьшился score после исключения совпавших компонентов. |
| `matched_accepted_case_ids` | `string[]` | ID применённых сохранённых норм без повторов. |

Пример фрагмента ответа:

```json
{
  "status": "БРАК",
  "anomaly_score": 0.81,
  "threshold": 0.25,
  "inspection_id": "8e87869d-...",
  "learned_normal_matches_count": 1,
  "learned_normal_adjustment": 0.14,
  "matched_accepted_case_ids": ["ea81f37c-..."]
}
```

## Endpoints обучения

### `GET /learning/reviews`

Возвращает недавние результаты `БРАК`, доступные для операторского разбора.

Query-параметр:

- `product_type` — необязательный фильтр.

Ответ:

```json
{
  "reviews": [
    {
      "inspection_id": "8e87869d-...",
      "product_type": "bucket",
      "reference_hash": "...",
      "created_at": "2026-08-11T12:00:00+00:00",
      "original_status": "БРАК",
      "original_score": 0.81,
      "threshold": 0.25,
      "defects_count": 2,
      "accepted_defects_count": 0,
      "counterfactual_score": null,
      "counterfactual_status": null,
      "pipeline_decision_sent": true
    }
  ]
}
```

### `GET /learning/reviews/{inspection_id}`

Возвращает один разбор и массив `defects`.

Основные поля дефекта:

| Поле | Описание |
|---|---|
| `id` | ID дефекта для операции `accept-as-normal`. |
| `bbox` | Прямоугольник `{x, y, width, height}` в пикселях. |
| `bbox_norm` | Тот же прямоугольник в координатах `0..1`. |
| `polygon` | Контур для отображения поверх изображения. |
| `area`, `score` | Площадь компонента и его локальная оценка. |
| `diff_mean`, `diff_q90`, `diff_max` | Статистика карты различий. |
| `accepted_as_normal` | Фрагмент уже совпал с сохранённой нормой. |
| `manually_accepted` | Оператор сохранил этот дефект из данного разбора. |
| `matched_case_id`, `similarity` | ID совпавшей нормы и близость, если совпадение найдено. |
| `affects_final_score` | Учитывался ли дефект при расчёте результата. |

Также возвращаются ознакомительные `counterfactual_score` и
`counterfactual_status`. Они показывают результат пересчёта старого кадра, но
никуда в конвейер не отправляются.

Ошибка: `404`, если разбор не найден или уже вытеснен из архива на диске.

### `GET /learning/reviews/{inspection_id}/image/{kind}`

Возвращает бинарное изображение разбора с заголовком `Cache-Control: no-store`.

Допустимые значения `kind`:

| `kind` | Ответ |
|---|---|
| `aligned` | Совмещённый текущий кадр, `image/jpeg`. |
| `heatmap` | Тепловая карта, `image/jpeg`. |
| `diff` | Карта различий, `image/png`. |
| `mask` | Исходная маска дефектов, `image/png`. |

Ошибка: `404` для неизвестного ID или `kind`.

### `POST /learning/reviews/{inspection_id}/defects/{defect_id}/accept-as-normal`

Сохраняет выбранный дефект как допустимую норму.

Тело запроса, `application/json`:

```json
{
  "note": "Допустимая складка этикетки"
}
```

Поле `note` необязательное, но JSON-тело требуется; можно передать `{}`.

Краткий ответ:

```json
{
  "saved": true,
  "accepted_case": {
    "id": "ea81f37c-...",
    "product_type": "bucket",
    "reference_hash": "...",
    "bbox_norm": {"x": 0.2, "y": 0.3, "width": 0.05, "height": 0.04},
    "area": 420,
    "note": "Допустимая складка этикетки",
    "enabled": true,
    "template_version": 2
  },
  "inspection_id": "8e87869d-...",
  "defect_id": "defect-1",
  "original_status": "БРАК",
  "original_score": 0.81,
  "counterfactual_status": "ГОДЕН",
  "counterfactual_score": 0.08,
  "affects_original_pipeline_decision": false,
  "pipeline_decision_sent": true
}
```

Ошибки:

- `404` — разбор или дефект не найден;
- `409` — дефект уже сохранён либо уже распознан как допустимая норма.

### `POST /learning/reviews/{inspection_id}/accept-all-as-normal`

Считать весь БРАК этого кадра ложным. Каждый видимый контур сохраняется
отдельным `accepted_case` со своим `id` (удаление по одному).

Тело запроса такое же, как у `accept-as-normal`. Поле `note` необязательное.

```json
{
  "saved": true,
  "accepted_cases": [{ "id": "ea81f37c-...", "product_type": "bucket#cam=0" }],
  "accepted_count": 2,
  "inspection_id": "8e87869d-...",
  "original_status": "БРАК",
  "original_score": 0.81,
  "counterfactual_status": "ГОДЕН",
  "counterfactual_score": 0.08,
  "affects_original_pipeline_decision": false,
  "pipeline_decision_sent": true
}
```

Ошибки: `404` — разбор не найден; `409` — нечего принимать.

### `GET /learning/accepted-cases`

Возвращает список сохранённых норм текущей сессии.

Query-параметр `product_type` необязателен. Ответ: `{"cases": [...]}`.
Элемент содержит `id`, `product_type`, `reference_hash`, `bbox_norm`, `area`,
статистику diff, `created_at`, исходные `inspection_id`/`defect_id`, `note`,
`enabled` и `template_version`.

### `GET /learning/accepted-cases/{case_id}/image`

Возвращает PNG-превью сохранённого фрагмента с зелёной подсветкой маски.

Ошибка: `404`, если норма не найдена.

### `DELETE /learning/accepted-cases/{case_id}`

Удаляет сохранённую норму. Следующие инспекции больше не будут применять это
исключение.

Ответ:

```json
{"deleted": true, "case_id": "ea81f37c-..."}
```

Ошибка: `404`, если норма не найдена.

## Встроенные страницы

- `GET /learning-review` — интерфейс оператора: список брака, кнопка
  «Дообучить этот БРАК», выбор одного контура, удаление норм.
- `GET /local-inspection-test` — локальная загрузка эталона и текущего кадра.
  На эталоне можно кликами задать ROI-полигон; инспекция, список дефектов и
  обучение будут учитывать только выбранную область. «Очистить» возвращает
  анализ всего кадра.

Эти страницы возвращают HTML и не включены в Swagger.

## Жизненный цикл и ограничения

- Разборы (`reviews`) пишутся на диск: `app/data/learning_reviews/{inspection_id}/`
  (`meta.json`, картинки, `defects.npz`). По умолчанию хранятся последние 50;
  лимит задаётся `ANALIS_LEARNING_REVIEW_LIMIT` в диапазоне `1..500`. При
  переполнении самый старый каталог удаляется (FIFO).
- Принятые нормы пишутся в `app/data/accepted_normals` только на время процесса.
- На старте сервиса оба каталога очищаются. После перезапуска Python ложняки
  и разборы предыдущей смены не действуют: свет, эталон и установка уже другие.
- Норма применяется только при совпадении `product_type` и `reference_hash`.
  После замены эталона старые нормы автоматически не действуют.
- Один сохранённый пример может исключить несколько похожих компонентов только
  рядом с исходным местом. Центры должны находиться в пределах 15% нормированного
  размера кадра; точное совпадение координат не требуется. Дальний одинаковый
  дефект и увеличение больше разрешённой границы не принимаются.
- Для уменьшенных вариантов нет нижней границы размера. Кроме общей маски
  дополнительно сравнивается устойчивое ядро `diff`; поэтому изменение масштаба
  и небольшое изменение толщины контура не требуют пиксельного совпадения.
  Порог этого режима — `0.76`, для общего сопоставления — `0.80`.
- Если рядом присутствует несколько подходящих компонентов, каждый сравнивается
  и исключается из итогового score отдельно. Для широкого блика кроп сравнивается
  с мини-эталоном в цвете: новый скол поверх знакомого засвета остаётся браком.
- Python-инспекция работает в фиксированных координатах камеры: ORB, ECC,
  гомография и центрирование не применяются. Поле
  `alignment_h_ref_to_cur` принимается для совместимости API, но Python его
  игнорирует. Если размеры текущего кадра и эталона отличаются, выполняется
  только обычный `resize` до размеров эталона. Поэтому можно передавать
  единичную матрицу:

```json
"alignment_h_ref_to_cur": [1, 0, 0, 0, 1, 0, 0, 0, 1]
```

## Типовой сценарий

1. Конвейер вызывает `/inspect-shm` и получает `БРАК` с `inspection_id`.
2. Оператор открывает `/learning-review` или получает разбор через API.
3. Оператор жмёт «Дообучить этот БРАК» (`accept-all-as-normal`) либо выбирает
   один `defect_id` и вызывает `accept-as-normal`.
4. Старый вердикт остаётся `БРАК`; возвращается только ознакомительный пересчёт.
5. В следующих инспекциях похожие компоненты вычитаются до итогового score.
6. При ошибочном обучении норма удаляется через `DELETE /learning/accepted-cases/{case_id}`.
