# Simple / Pro — подписи и пояснения для фронта

Готовые тексты для UI: **название на экране** + **короткая подсказка** (tooltip / helper text).  
Технический маппинг: [ANALYSIS_SETTINGS_SIMPLE_PRO.md](ANALYSIS_SETTINGS_SIMPLE_PRO.md).

Все ручки (кроме порога) — слайдеры **`0 … 1`**, середина **`0.5`** = заводской баланс.

---

## Что возвращают эндпоинты

Базовый URL: `http://127.0.0.1:8000`  
`GET` и `PUT` одного режима возвращают **один и тот же shape**.  
Middleware всегда добавляет `detector_id`.

### Поля ответа (общие)

| Поле | Тип | Для фронта |
|------|-----|------------|
| `analysis_profile` | `string` | Профиль / product_type из URL |
| `knobs` | `object \| null` | Значения ручек для слайдеров. `null` — этот режим ещё не сохраняли (или сбили полным API) |
| `settings` | `object` | Эффективные настройки алгоритма (defaults ⊕ overrides) — то, что реально идёт в инспекцию |
| `defaults` | `object` | Заводские значения 18 полей (для сравнения / «сброс к норме») |
| `overrides` | `object` | Только переопределённые поля, как лежит в JSON |
| `detector_id` | `string` | Id инстанса детектора (добавляет middleware) |

### `GET/PUT /analysis-settings/{profile}/simple`

**Тело PUT:**

```json
{ "threshold": 0.25, "sensitivity": 0.5 }
```

**Ответ:**

```json
{
  "analysis_profile": "bench-lan1",
  "knobs": {
    "threshold": 0.25,
    "sensitivity": 0.5
  },
  "settings": {
    "default_threshold": 0.25,
    "use_patchcore": true,
    "min_defect_area": 6,
    "min_scratch_aspect": 3.0,
    "min_diff_signal": 12.0,
    "diff_percentile": 98.0,
    "scratch_score_floor": 0.35,
    "scratch_aspect_floor": 4.5,
    "edge_suppress_factor": 0.2,
    "text_min_contrast": 55,
    "text_structure_threshold": 30,
    "contrast_loss_boost": 2.0,
    "contrast_loss_ref_grad": 40.0,
    "contrast_loss_cur_grad": 15.0,
    "enable_clahe": true,
    "clahe_clip_limit": 1.2,
    "fp_recheck_enabled": true,
    "fp_trigger_diff_q90": 22.0
  },
  "defaults": { "...": "те же 18 ключей, заводские" },
  "overrides": { "...": "что реально записано в профиль" },
  "detector_id": "..."
}
```

| Что биндить в UI | Откуда |
|------------------|--------|
| Слайдеры simple | `knobs.threshold`, `knobs.sensitivity` |
| Если `knobs === null` | слайдеры в дефолт `threshold=0.25`, `sensitivity=0.5` (или показать, что режим не активен) |
| «Что применилось» | `settings` (обычно фронту не показывать все 18, кроме отладки) |

`PUT` сразу сохраняет и возвращает уже записанное состояние.

### `GET/PUT /analysis-settings/{profile}/pro`

**Тело PUT:**

```json
{
  "threshold": 0.25,
  "noise_tolerance": 0.5,
  "scratch_sensitivity": 0.5,
  "edge_suppression": 0.5,
  "text_handling": 0.5,
  "preprocess_strength": 0.5
}
```

**Ответ:**

```json
{
  "analysis_profile": "bench-lan1",
  "knobs": {
    "threshold": 0.25,
    "noise_tolerance": 0.5,
    "scratch_sensitivity": 0.5,
    "edge_suppression": 0.5,
    "text_handling": 0.5,
    "preprocess_strength": 0.5
  },
  "settings": { "...": "18 полей алгоритма" },
  "defaults": { "...": "заводские 18 полей" },
  "overrides": { "...": "переопределения профиля" },
  "detector_id": "..."
}
```

| Что биндить в UI | Откуда |
|------------------|--------|
| Слайдеры pro | все поля из `knobs` |
| Если `knobs === null` | дефолты `0.5` на ручках (и `threshold` из `settings.default_threshold`, если нужно) |

После `PUT /simple` у `GET /pro` будет `knobs: null` (и наоборот) — активен только один abstract-режим.

### Ошибки (фронту)

| Код | Когда |
|-----|--------|
| `422` | Невалидное тело: порог не в `(0, 1]`, ручка не в `[0, 1]` |
| `400` | Редкая внутренняя ошибка валидации expand |

## Simple (2 ручки)

| API-поле | Название на фронте | Мини-пояснение |
|----------|--------------------|----------------|
| `threshold` | Порог брака | Выше — реже брак, ниже — чувствительнее к дефектам |
| `sensitivity` | Чувствительность | Общая «чуткость» алгоритма. Меньше — меньше ложных срабатываний, больше — ловит слабые дефекты |

### Подсказки для слайдеров (simple)

**Порог брака** (`threshold`)
- Левый край (низкий): чаще вердикт «БРАК»
- Правый край (высокий): чаще вердикт «ГОДЕН»

**Чувствительность** (`sensitivity`)
- `0` — Грубо
- `0.5` — Норма
- `1` — Максимум

Краткий helper под блоком:
> Две настройки для быстрой калибровки. Порог решает ГОДЕН/БРАК по score, чувствительность подкручивает остальной алгоритм.

## Pro (6 ручек)

| API-поле | Название на фронте | Мини-пояснение |
|----------|--------------------|----------------|
| `threshold` | Порог брака | Выше — реже брак, ниже — чувствительнее к дефектам |
| `noise_tolerance` | Отклик на шум | Насколько сильно реагировать на мелкий шум и слабые отличия. Выше — ловит мелочь, ниже — спокойнее к шуму |
| `scratch_sensitivity` | Чувствительность к царапинам | Насколько охотно ловить тонкие длинные дефекты |
| `edge_suppression` | Реакция на края | Насколько учитывать отличия у границ и рамок. Выше — края виднее, ниже — края глушатся сильнее |
| `text_handling` | Работа с текстом / печатью | Чувствительность к отличиям на надписях и к пропаже контраста текста |
| `preprocess_strength` | Предобработка изображения | Сила выравнивания контраста перед анализом. Выше — локальные различия заметнее |

### Подписи краёв слайдеров (pro)

| Ручка | Слева (`0`) | Центр (`0.5`) | Справа (`1`) |
|-------|-------------|----------------|--------------|
| Порог брака | Чувствительнее | — | Строже к браку |
| Отклик на шум | Спокойнее | Норма | Агрессивнее |
| Чувствительность к царапинам | Слабее | Норма | Сильнее |
| Реакция на края | Глушить края | Норма | Учитывать края |
| Работа с текстом / печатью | Спокойнее | Норма | Чутьче |
| Предобработка изображения | Слабее | Норма | Сильнее |

Краткий helper под блоком:
> Расширенная настройка по группам. Каждая ручка крутит свой набор внутренних параметров; порог — отдельно от детекции.

## Тосты / статусы (опционально)

| Событие | Текст |
|---------|-------|
| Успешный PUT simple/pro | Настройки сохранены |
| `knobs === null` при GET | Режим не задавался через быстрые настройки — показаны текущие значения алгоритма |
| Ошибка валидации | Проверьте значения: порог от 0 до 1 (больше 0), остальные ручки от 0 до 1 |

## Чеклист для UI

1. Simple: два контрола — **Порог брака**, **Чувствительность**.
2. Pro: шесть контролов с названиями из таблицы выше.
3. После сохранения показывай из ответа поле `settings` (или хотя бы score-порог), если нужен «что реально записалось».
4. Не называй на фронте внутренние поля (`min_diff_signal` и т.п.) — только abstract-ручки.
5. Единицы не нужны: все ручки безразмерные `0…1`, порог тоже доля score.
