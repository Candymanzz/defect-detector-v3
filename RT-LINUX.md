# Привязка приложения к CPU в Ubuntu

На текущем компьютере CPU 0 и 6 относятся к одному физическому ядру,
1 и 7 — к следующему, далее пары 2/8, 3/9, 4/10, 5/11.

Запуск из каталога проекта:

```bash
bash ./run-rt.sh
```

По умолчанию приложение использует CPU `2-5,8-11` (четыре физических
ядра). Supervisor, запускаемый им оркестратор и новые дочерние процессы
наследуют привязку. Уже работающие сторонние процессы она не меняет.
Программа, которая сама меняет свою affinity, может переопределить её.

Другой набор CPU и запуск без интерфейса:

```bash
IML_CPUSET=2,8 bash ./run-rt.sh --no-frontend
```

Переменная `CONFIG` поддерживается как в `run-supervised.sh`. Для запуска
нужны существующий конфиг (по умолчанию `config/config.yaml`), собранный
JAR оркестратора и зависимости сервисов.

Проверка всех потоков процесса (подставьте PID):

```bash
taskset -apc PID
```

Привязка ограничивает приложение выбранными CPU, но система и другие
приложения также могут использовать их. Изоляция CPU, размещение IRQ
и приоритеты реального времени требуют отдельной настройки под период
цикла приложения и измерения задержек. Скрипт их не меняет.

Для запуска без этой привязки используйте `bash ./run-supervised.sh`.

## Изоляция CPU при загрузке на этом компьютере

Ядро 6.8.1-1015-realtime поддерживает NO_HZ_FULL и RCU_NOCB_CPU.
Подготовленный файл добавляет изоляцию планировщика для CPU 2-5,8-11,
переносит обычные IRQ по умолчанию и несвязанные kernel threads на
0,1,6,7. managed IRQ перенаправляются по возможности; абсолютного
отсутствия прерываний и системной работы это не гарантирует.
Полное подавление тика требует не более одной исполняемой задачи на CPU;
многопоточный стек приложения не всегда выполняет это условие.

Установка из корня проекта (требует sudo):

```bash
sudo install -m 0644 tools/90-iml-cpu-isolation.cfg /etc/default/grub.d/90-iml-cpu-isolation.cfg
sudo update-grub
```

После успешного update-grub перезагрузитесь. Проверка:

```bash
cat /proc/cmdline
cat /sys/devices/system/cpu/isolated
cat /sys/devices/system/cpu/nohz_full
```

Два последних файла должны показывать `2-5,8-11`. Приложение запускайте
через `bash ./run-rt.sh`, чтобы оно попало на изолированные CPU.
Другие процессы с явно назначенной affinity могут также попасть туда.

Если установлен irqbalance, его политику нужно отдельно ограничить CPU
системы: `IRQBALANCE_BANNED_CPULIST=2-5,8-11` в окружении службы.
Изоляция domain отключает обычную балансировку между выделенными CPU;
распределение потоков приложения между ними нужно проверять под нагрузкой.

Отмена (имя файла изменяется так, чтобы GRUB перестал читать его):

```bash
sudo mv /etc/default/grub.d/90-iml-cpu-isolation.cfg /etc/default/grub.d/90-iml-cpu-isolation.cfg.disabled
sudo update-grub
```

Затем перезагрузитесь. При проблемах загрузки нажмите `e` в GRUB,
удалите добавленные параметры из строки `linux` и загрузитесь Ctrl+X.
Это изменение действует только на одну загрузку; затем отмените настройку.
