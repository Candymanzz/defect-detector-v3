# PLC register map (Omron MAP 25_247)

Исходные экспорты из CX-Programmer / MAP — файлы `25_247_MAP - *.csv`.

**Рабочая карта для оркестратора:** `register-map.yaml` — её и правьте руками.

## Как поменять сигнал по FINS без правки кода

1. Откройте `plk/register-map.yaml`.
2. Найдите сигнал по `name` или добавьте новый блок в `signals:`.
3. Поля, которые реально едут в FINS:
   - `area` — `CIO` / `W` / `H` / `DM`
   - `address` — `"слово.бит"` (как в таблице: `0.06`, `240.00`)
   - `direction` — `pc_to_plc` (пишем) или `plc_to_pc` (только читаем)
4. Перезапустите оркестратор (карта грузится при старте).

Служебные имена (не переименовывать): `vision_ready`, `vision_fault`, `reject_line_1`, `reject_line_2`.
На них ссылаются `plc_fins.vision_*_signal` и выбор линии брака по `bucket_group_id`.

## Техзрение PC→PLC (лист «Входы»)

| Сигнал | Адрес FINS | direction |
|--------|------------|-----------|
| `vision_ready` | **W0.04** | `pc_to_plc` |
| `vision_fault` | **W0.05** | `pc_to_plc` |
| `reject_line_1` | **W0.06** | `pc_to_plc` |
| `reject_line_2` | **W0.07** | `pc_to_plc` |

## Лист «Состояния / Неисправности / Управление» → FINS (чтение / управление)

| Колонка | Слова CIO | direction | Что делает оркестратор |
|---------|-----------|-----------|-------------------------|
| Состояния | 140… | `plc_to_pc` | читает биты |
| Неисправности | 191… | `plc_to_pc` | читает биты |
| Управление | 240… | `pc_to_plc` | пишет биты (сброс аварий и т.п.) |

## Два канала на брак / ready / fault

| Канал | Когда | Куда |
|-------|-------|------|
| FINS | runtime ready/fault/reject | **W0.04–W0.07** |
| Discrete DO | только Line0 (съёмка), не брак | IO-box |

Таймауты отбраковки всегда по FINS: **D4400–D4404** (секция `timeouts`).
