# Конфигурация

`config.yaml` импортирует общие блоки из `blocks/`. Эти файлы хранятся в Git.
Исходные настройки перенесены 2026-11-09 с `femboy36:~/Документы/core-dev/config/`
(ветка `boobs+pasha`, HEAD `832e4fc0`), а не из старой локальной папки.
Исторические обёртки `python-before-cpp-*` и `cpp-linux-femboy36-*` объединены
в `config.yaml`; их overrides сохранены.

Все IPv4-адреса задаются только в **локальном `ips.yaml`**, исключённом из Git.
На новой машине выполните из корня репозитория:

```bash
python3 deploy/init-ips.py
```

Команда запросит адреса, проверит IPv4 и откажется перезаписывать существующий файл.
Можно передавать значения через повторяемый аргумент `--set camera_0=АДРЕС`.
Имена ключей берутся из ссылок в общих YAML:

- `camera_0` … `camera_9` — камеры по ID;
- `light_mv-le-1` … `light_mv-le-4` — Ethernet-контроллеры света по ID;
- `plc` — ПЛК;
- `loopback` — локальные API/WS и адреса локальных сервисов;
- `any` — привязка UDP ко всем интерфейсам.

`ip_config: ips.yaml` задаёт путь относительно главного YAML. После слияния
импортов Java раскрывает `${ip:camera_0}`, `${ip:plc}` и другие ссылки во всех
строках, включая URL и аргументы команд. Отсутствующий файл, ключ или невалидный
IPv4 останавливает загрузку; скрытой подстановки адресов по умолчанию нет.
Ссылки на другие ключи внутри `ips.yaml` не поддерживаются.
При добавлении устройства добавьте его ссылку в общий YAML и адрес в локальный файл.

Настройки камер больше не дублируются в ручном JSON. Перед открытием JNI Java
атомарно записывает `config/.camera-worker.generated.json` из уже раскрытого YAML.
Этот внутренний файл игнорируется Git; редактировать его не нужно. Он лежит рядом
с главным конфигом, поэтому нативная библиотека продолжает читать сохранённые
настройки из `config/data/camera_runtime_settings.json`. `config/data/` — локальное
состояние оператора, не общие настройки; его JSON-формат не менялся.
Явный `integration.worker_config_json` оставлен для старых установок и нативных
тестов: при его использовании Java не генерирует JSON и читает указанный файл.
Для штатного запуска этого параметра в конфиге нет.
Standalone `camera_worker` принимает сгенерированный JSON; он сам не читает YAML.

В `blocks/01-core.yaml` сохранён выбранный владельцем `Bayer RG 12 Packed`.
JNI распознаёт это имя и `BayerRG12Packed`, выставляет BayerRG12Packed через SDK
и преобразует 12-битную мозаику в BGR8 для существующего SHM/детектора.
Сетевой payload — 1.5 байта/пиксель; downstream остаётся 8-битным BGR.
Неподдерживаемый формат приводит к ошибке открытия вместо переключения на BGR8.
Проверка SDK на синтетических кадрах не подтверждает работу этого режима на камерах.

Linux-команда C++ использует отслеживаемый путь
`cppAnalisSurface/build/cpp_analis_surface`; старый серверный wrapper из игнорируемого
`tools/` не нужен при установленных системных OpenCV-библиотеках.
Если конкретной машине нужен свой `LD_LIBRARY_PATH`, задайте его в окружении сервиса.
COM/serial, SDK-пути, FINS dest_node/src_node остаются обычными параметрами YAML;
смена IP ПЛК сама по себе не пересчитывает FINS node.

На сервере исходные файлы и работающие процессы при переносе не менялись.
