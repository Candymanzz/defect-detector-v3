# Linux + C++ detector

Ветка `линукс+кресты` сохраняет Linux-захват камер через JNI, встроенные MVS IO/свет,
отбраковку и управление киоском из `testlinux`. Детектор, настройки стыка и React-интерфейс
перенесены из `cpp-detector`. Инспекция поверхности выполняется отдельным C++-процессом,
Python-сервис для неё не запускается. Python 3 нужен только служебным Linux-скриптам.

## Зависимости и сборка

Ubuntu 24.04, JDK 17+, Maven, Node.js >=20.19, установленный MVS SDK:

```bash
sudo apt update
sudo apt install build-essential cmake pkg-config libopencv-dev libcpp-httplib-dev nlohmann-json3-dev
bash ./rebuild-and-run.sh -f
```

Собираются оркестратор, Java-геометрия, JNI камер и C++-детектор. Без `-f` также
собирается и устанавливается интерфейс киоска в `/opt/defect-detector-ui`.
Сборка не останавливает и не запускает рабочие сервисы. По умолчанию C++ собирается
двумя потоками; `IML_BUILD_JOBS=4` меняет это число.

```bash
bash cppAnalisSurface/build.sh           # только C++
bash ./rebuild-and-run.sh -c -o -g       # C++ и фронт
bash ./rebuild-and-run.sh -c -o -g -d    # только фронт
bash ./rebuild-and-run.sh -f -d -g       # оркестратор и JNI камер
```

Linux собирается в `cppAnalisSurface/build-linux`, исполняемый файл публикуется
как `cppAnalisSurface/build/cpp_analis_surface`. Замена через rename сохраняет старый
образ работающего процесса до отдельного перезапуска. Windows CMake-кэш не используется.
Системная cpp-httplib 0.14 из Ubuntu поддерживается через pkg-config и regex-маршруты.

## Конфигурация существующего станка

Не заменяйте рабочие настройки камер, IO и сети шаблоном. Создайте отдельный профиль,
импортирующий прежний YAML и переопределяющий только детектор и его параллелизм:

```bash
python3 deploy/linux/configure-cpp-detector.py --config config/config.yaml --workers 4
CONFIG=config/cpp-linux.yaml bash ./run-supervised.sh -f
```

Профиль создаётся один раз; существующий файл не перезаписывается. Для systemd нужно
отдельно передать этот CONFIG в окружение службы. Старые пороги Python автоматически
не преобразуются: C++ использует другой алгоритм и собственные настройки профилей.
Проверьте настройки и качество на сохранённых нормальных/дефектных кадрах до работы линии.

Для нового стенда можно скопировать `config.exemple` в `config`: в шаблоне уже выбран
`python_detector.backend: cpp`. Название секции сохранено для совместимости Java API.

Один сервер: `python_server_pool_size: 1`. Java отправляет до 10 запросов параллельно
(`python_parallelism`, `python_request_parallelism`, `server_concurrency`), а
`analis_surface_autostart.inspect_workers: 4` ограничивает число вычислений внутри C++.
Для i7-8700 сравните 4, 6 и 8 обработчиков по p95/p99 полного цикла. Оптимум не установлен.

C++ наследует набор CPU запускающего процесса. Не запускайте его через старую
`tools/run-analis-isolated.sh`, закрепляющую Python-процесс за одним CPU. `run-rt.sh`
сохраняет прежний профиль; задавайте `IML_CPUSET` по реально доступным CPU/cgroup и
конфигурации изоляции станка. 12 логических CPU не равны 12 физическим ядрам.

Эталоны и кадры передаются через `/dev/shm`; текущая реализация C++ копирует вход в
собственный `cv::Mat`. Настройки из UI хранятся в `cppAnalisSurface/data/settings.json`.
Heatmap формируется синхронно: Python-опции отложенного рендера здесь отключены.
`stop-dev.sh` распознаёт C++ даже после потери родительского процесса.

## Проверки

```bash
bash ./run-all-tests.sh
# Старый Python проверяется только при явном запросе:
bash ./run-all-tests.sh --legacy-python
```

Основной набор проверяет Java, C++ и фронт. `CppDetectorLinuxIntegrationTest` запускает
отдельный C++ на свободном порту: 10 синтетических камер через реальный Java HTTP-клиент,
SHM со stride/offset, настройки, heatmap, брак и повторную загрузку потерянного эталона.
Он не обращается к камерам или ПЛК. Тесты JNI используют синтетический backend.

Подробные тайминги: `logs/performance`, описание полей —
[`PERFORMANCE_LOGGING.md`](../../cppAnalisSurface/PERFORMANCE_LOGGING.md).
На Linux отбраковка может идти через встроенные MVS IO: событие FINS само по себе не
описывает этот путь. Замеры на синтетике не подтверждают 500 мс от аппаратного триггера
до выхода на реальном станке.
