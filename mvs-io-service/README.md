# Linux MVS IO: DO6 / Timer6

## Пробел → Timer6 → DO6 (контроллер на последовательном порту)

Для текущего запроса используйте **keyboard.py**, а не прежний HTTP-сервис.
На этой машине SDK обнаружил `MV-VC3704H-128G60`, серийный номер `DA8813541`,
на порту `COM_Port#ttyS4`. Его GenICam XML содержит команду **TriggerSoftware**,
а не `TimerTriggerSoftware` из примеров других устройств.

В MVS уже должны быть настроены DO6 от Timer6 и Timer6 от Software. Длительность,
задержка и режим таймера берутся из устройства и скриптом не изменяются.
Сохраните настройки штатным способом MVS, если необходимо сохранять их после
перезапуска устройства. Освободите устройство в MVS перед запуском, если порт занят.

Из корня проекта:

```bash
python3 mvs-io-service/keyboard.py --port 'COM_Port#ttyS4' --serial DA8813541
```

Нажмите пробел в этом терминале: команда отправится сразу, Enter не нужен.
Сервис читает маршрут Out6 → Timer6, полярность выхода и длительность таймера.
Если маршрут неверный, запуск прекращается. Для визуальной проверки лампочкой
можно временно сделать длительность 1 секунду:

```bash
python3 mvs-io-service/keyboard.py --port 'COM_Port#ttyS4' --duration-ms 1000
```

Исходная длительность восстанавливается при нормальном выходе, Ctrl+C и ошибке.
Для диагностики принятой команды без видимого сигнала:

```bash
python3 mvs-io-service/keyboard.py --port 'COM_Port#ttyS4' --duration-ms 1000 --watch
```

`--watch` читает LineStatus Out6 до команды и после неё (примерно 0/50/200/500 мс).
Это показания контроллера, а не измерение напряжения на клемме. Сэмплы могут
пропускать короткие импульсы, а задержки зависят от скорости SDK. Каждый запуск
повторно выбирает Timer6 и проверяет Software непосредственно перед командой.
В диагностическом режиме обработка следующего нажатия ждёт окончания этих чтений.

При принудительном завершении SIGKILL или отключении питания восстановление
не выполняется. Это не меняет задержку, режим Burst/Continuous или число импульсов.

Выход: `q`, Esc или Ctrl+C. При удержании пробела автоповтор клавиатуры может
давать повторные импульсы; минимальный интервал по умолчанию 150 мс
(`--debounce-ms`). Это не аппаратная длительность импульса.

При старте ничего не запускается на выходах. Скрипт только выбирает Timer6,
проверяет Software и доступность команды. При выходе возвращает исходный
TimerSelector, освобождает порт и восстанавливает настройки терминала.
Связь DO6 с Timer6 установлена пользователем в MVS; скрипт её не переписывает.
Успешный ответ SDK не является измерением физического сигнала на DO6.

Диагностика без запуска импульсов:

```bash
python3 mvs-io-service/keyboard.py --list
python3 mvs-io-service/keyboard.py --check --port 'COM_Port#ttyS4' --serial DA8813541
```

Если контроллер ровно один, `--port` и `--serial` можно опустить. При нескольких
контроллерах выбор нужно указать явно. Скрипт перечисляет только последовательные
устройства MVS и выбирает только модель с префиксом `MV-VC`.

## Предыдущий диагностический HTTP-сервис DO6 / Timer6

Отдельный диагностический HTTP-сервис на Python 3, без дополнительных pip-пакетов.
Использует установленный Linux MVS `/opt/MVS`, его Python-структуры и реальные
функции `libMvCameraControl.so`. Windows DLL не используются.

## Проверка доступности оборудования

Из корня репозитория:

```bash
python3 mvs-io-service/service.py --list
```

Перечисляются интерфейсы световых контроллеров, виртуальных карт и frame grabber.
Обычные камеры намеренно не выбираются как встроенные DO контроллера.
Пустой список означает, что через этот интерфейс установленного MVS SDK
устройство не обнаружено. Он не доказывает отсутствие IO-платы.

В этой системе последовательные порты принадлежат `root:dialout`, пользователь
`o` не состоит в `dialout`. Для предоставления доступа выполните в терминале:

```bash
sudo usermod -aG dialout o
```

Затем полностью выйдите из пользовательского сеанса Ubuntu и войдите снова.
Проверьте `id` и повторите `--list`. Имена Windows `COM3` нельзя механически
заменять на `/dev/ttyS2`: привязку внутреннего IO к порту требуется установить.
Доступ к порту не добавляет отсутствующие драйверы или поддержку IO в SDK.

## Проверка узлов и один импульс

Когда `--list` вернёт интерфейс **нужного контроллера**, используйте его точный ID:

```bash
python3 mvs-io-service/service.py --interface-id 'ID_ИЗ_СПИСКА' --inspect
```

Проверяются `TimerSelector`, `TimerTriggerSource`, `LineSelector`, `LineMode`,
`LineSource`, `TimerDuration`, `TimerDelay`. `--inspect` только читает текущие
узлы; зависимые узлы относятся к текущим селекторам.

```bash
python3 mvs-io-service/service.py --interface-id 'ID_ИЗ_СПИСКА' --line DO6 --configure --pulse
```

Это одна попытка: Timer6 → Software, выбранный выход → Output / Timer6Active,
затем команда `TimerTriggerSoftware`. Значения принимаются только если SDK
явно сообщает об их поддержке. Если выход называется иначе, задайте `--line`
по документации устройства: сервис не предполагает, что Line6 соответствует DO6.
Продолжительность и задержка берутся из текущих настроек Timer6 в устройстве.
Опция `--duration-native N` вместе с `--configure` меняет длительность в единицах
SDK; единицы нужно проверить в документации/интерфейсе MVS, это не обязательно
миллисекунды. Сервис проверяет диапазон и шаг.

Маршрут и настройки, записанные с `--configure`, остаются в оперативной
конфигурации устройства (без SaveParam). При ошибке настройки могут быть
применены частично; исходные LineSelector и TimerSelector восстанавливаются.
Возврат `sdk_command_accepted` означает только принятие команды SDK.
Физический сигнал нужно проверить на DO6; сервис его не измеряет.

## HTTP

```bash
python3 mvs-io-service/service.py --interface-id 'ID_ИЗ_СПИСКА' --line DO6 --configure
curl http://127.0.0.1:9116/interfaces
curl http://127.0.0.1:9116/nodes
curl -X POST http://127.0.0.1:9116/pulse
```

Сервис слушает только localhost. При старте импульс не выдаётся.
`GET /health` подтверждает загрузку SDK, а не готовность оборудования.
Без `--interface-id` HTTP-сервис работает в диагностическом режиме;
`POST /pulse` возвращает ошибку, не выбирая случайное устройство.

Оригинальные примеры API находятся в установленном MVS:
`/opt/MVS/Samples/64/C++/LightController/ConfigLightController/ConfigLightController.cpp`
и `/opt/MVS/Samples/64/C++/FrameGrabber/QtCreator/InterfaceBasicDemo/gevconfigform.cpp`.

Проверки без оборудования:

```bash
python3 -m unittest discover -s mvs-io-service -p 'test_*.py'
```
