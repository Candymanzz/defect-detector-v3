## Изменение

`InspectionSlots::Lease` заменяет счётчик Service::Slot: резервирует свободный
слот и назначает HTTP-потоку один CPU через pthread_setaffinity_np. Одновременно
работающие инспекции получают разные физические ядра. Слот удерживается на
чтении SHM, подготовке, ECC, сравнении, дообучении и шве; heatmap остаётся снаружи.
Исходная маска восстанавливается и слот освобождается также при исключении.
Ошибка установки affinity прерывает запрос и возвращает слот; ошибка
восстановления маски пишется в stderr, слот всё равно освобождается.

CLI `--inspect-cpus 3-5` приоритетнее env `ANALIS_INSPECT_CPUS`. Количество CPU
должно совпадать с workers. Проверяются синтаксис, дубликаты, унаследованная маска,
sysfs-топология и отсутствие SMT-соседей одного ядра. Пустая настройка сохраняет
прежний режим. На других ОС непустой список вызывает понятную ошибку запуска;
в Windows-команду он не добавлен. Windows-сборка не проверялась.

В config/config.yaml workers3, Linux CLI CPU3–5. Тяжёлый анализ не занимает
физическое ядро CPU2/8, где в рабочем снимке исполнялась Java. Общая маска
run-rt/systemd2-5,8-11 прежняя; Java/фоновые HTTP-потоки не получили отдельную
жёсткую affinity. Это разделение вычислительных слотов, а не абсолютная изоляция
всех Java/IO-потоков. Конфигурация привязана к топологии данной машины.
Windows также получает workers3, без affinity.

Health дополнен inspect_cpus, startup log содержит маску, performance-записи —
inspect_cpu вне объекта ms. Реальное исполнение проверено отдельно через /proc.
ECC512/30 итераций/epsilon1e-6, пороги, геометрия, settings.json, нормы, зоны,
defer-флаги, свет, PLC/DO, isolcpus и приоритеты production не менялись.
