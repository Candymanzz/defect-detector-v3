## Актуальность и границы

**Проверено по исходникам:** до этой задачи в текущем checkout не было `exclusions` /

они не являются описанием серверного контракта из вложения. Указанные во вложении
9/9 CTest и 28/28 JUnit относятся к внешней серверной работе и здесь не перепроверялись.

## Реализованное поведение

После уточнения 2026-11-10 раздел «Зоны исключения инспекции» расположен
в тестовом окне отдельной камеры. В боковой панели и режиме всех камер редактора нет: геометрия зон
принадлежит эталону конкретной камеры.

- Замкнутые многоугольники рисуются отдельным SVG-слоем с голубой заливкой; черновик зелёный.
  Можно добавить несколько зон, убрать точку, завершить/отменить рисование,
  выбрать зону из списка или на изображении, удалить одну/все зоны,
  отменить последнее изменение или весь черновик.
- Формат — массив многоугольников с парами `[x,y]`, нормализованными в 0..1.
  Пересчёт использует исходные `W-1`, `H-1`, фактические границы и масштаб изображения;
  поля при `contain` не считаются частью картинки. При загрузке/ошибке изображения
  рисование недоступно. С уточнения 2026-11-10 есть zoom/pan с пересчётом по
  преобразованному SVG и перетаскиванием вершин; формат API сохранён.
- Локальная проверка: до 32 зон, 3–128 точек, конечные координаты 0..1,
  ненулевая площадь, отсутствие самопересечений/самокасаний и повторяющихся соседних вершин.
  Перекрытие разных зон разрешено. Серверная проверка остаётся необходимой.
- Чтение/сохранение идут через Java
  `/api/orchestrator/detector-settings/camera/{id}`. PUT зон содержит только
  `{exclusions: [...]}`. Удаление всех — PUT `{exclusions: []}`, без DELETE.
  После ответа используется `response.settings.exclusions`.
- Подтверждённое состояние отделено от черновика. Повторное сохранение блокируется;
  после ошибки PUT выполняется GET, черновик сохраняется. Если GET тоже не удался,
  дальнейшая запись и TEST с черновиком блокируются до успешного перечитывания.
  Повтор первоначально неудачного GET загружает серверные зоны, а не оставляет
  неинициализированный пустой черновик.
- Модель редактора создаётся отдельно для камеры. Поздние ответы не изменяют
  редактор другой камеры. Начатое сохранение относится к исходной камере.
- Обычная форма отправляет только редактируемые ею числовые поля и seam,
  исключая `exclusions` и незнакомые серверные настройки. В режиме всех камер также
  исключается seam. PUT/DELETE одной камеры сериализуются в общем API-слое;
  GET ждёт уже поставленные записи этой камеры.
- Кнопка «Сбросить весь профиль» сохраняет прежнюю семантику DELETE всех настроек;
  после сброса перечитываются зоны. Для удаления только зон используются кнопки редактора.
- В тестовом окне «Проверить» отправляет черновик, включая явный `[]`, через
  `temporarySettings.analysis.settings.exclusions`. Незавершённый контур блокирует
  отправку. «Сохранить» сохраняет настройки/зоны, затем использует
  существующую постановку задания и ожидание `server.inspect_result`.
  Снимок для TEST берётся до уведомления других форм о перечитывании настроек,
  чтобы синхронное начало GET не блокировало получение только что сохранённого черновика.
  Сохранение числовых настроек и списка зон — отдельные PUT, общей транзакции между ними нет.

В TEST-окне кнопки «Проверить»/«Сохранить» закреплены в отдельной нижней панели;
редактор зон находится во внутренней области прокрутки настроек.
[Компоновка, границы и проверки](../ui/test-frame-settings.md).

Интерфейс поясняет, что новые дефекты внутри исключений тоже игнорируются,
исключения отличаются от дообучения и сохраняются при смене эталона.
Изменения не редактируют ROI, seam-линии эталона и обученные нормы.

## Результат и история

В API/WS-типы добавлен необязательный `inspection_exclusions`:
`polygons`, `coordinate_space: "normalized"`, `surface_skipped`, `remaining_area_work_px`.
Он переносится из архивной истории и последнего snapshot в результат камеры.
В подробном результате и карточках истории показываются число зон, рабочая площадь,
отдельный признак полного исключения поверхности и раскрываемая схема многоугольников.
Источник схемы — снимок именно этой инспекции; текущий профиль/черновик не подставляются.
Старые записи без поля отображаются без этого блока и не объявляются полностью исключёнными.

Контуры результата показаны на отдельной нормализованной схеме. Наложение на сырой
непозиционированный кадр не выполняется: подтверждённого преобразования координат
результата в контракте нет. Это компромисс точности визуализации; на эталоне
редактора полноценное наложение есть. Общий вердикт, PLC и обработка отказа геометрии
остаются серверными; `surface_skipped` их не заменяет.

## Проверки

Локально выполнены:

- `npm run build` — TypeScript и production Vite build.
- `npm test` — **85/85** тестов в **21** файле Vitest.
  Покрыты валидация геометрии/масштаба, undo/cancel, повтор после ошибки,
  неопределённый результат PUT, загрузки разных камер, последовательность записей,
  частичный HTTP-контракт, вложенность TEST, пустые/старые результаты и архивный снимок.
- ESLint всех новых модулей и изменённых файлов, кроме прежней ошибки
  `react-hooks/set-state-in-effect` в `ModalWrapper.tsx` (геометрическая панель).
  Та же ошибка подтверждена отдельным запуском ESLint на содержимом файла из HEAD;
  правки этой задачи её не добавили.
- Изолированный Chromium/Electron с имитацией API: 17 сценарных проверок,
  включая реальные клики по эталону, несколько зон, удаление/undo/cancel,
  временный TEST-пакет, HTTP 400 и повтор, сохранение неизвестных настроек,
  явную очистку и смену камеры во время PUT. Скриншот просмотрен.
  Локальный стенд находится в игнорируемой `.tmp/inspection-exclusions-2026-11-09/`;
  он не является обязательной зависимостью проекта.

**Не проверено:** реальный обновлённый C++/Java backend, производственные дефекты
внутри/снаружи исключений, сохранность после рестарта backend, полный TEST flow
с настоящим WS, камера/PLC, Linux и бюджет 500 мс. Работающий production runtime
не обновлялся. API не имеет revision/ETag: разные вкладки/клиенты и камеры с общим
`analysis_profile` разделяют серверное состояние; общей блокировки между ними нет.
