# Выборка этикетки из полного кадра — 2026-11-16

Проект `detector-/defect-detector-v3`, ветка `comp+`. В начале задачи рабочее
дерево было чистым. Перенос алгоритма из другого репозитория не выполнялся:
исправлен действующий путь компенсации с подтверждённым контуром.
Исходный HEAD: `0f65f71f`.

## Проблема и решение

Раньше ограничение видимости строилось из неподвижного ROI текущего кадра,
после чего переносилось обратно в координаты эталона. Если этикетка перемещалась
за прежний ROI, часть её пикселей исчезала из проверки, хотя на фотографии
она оставалась видна. Это особенно опасно для повреждений у верхнего края.

Теперь ROI задаёт область **на эталоне**. Соответствующие пиксели текущей
этикетки берутся из полного исходного кадра по уже измеренному сдвигу.
Путь `alignRoiInspectionGray` уже умел обращаться к полному изображению;
ошибка была в дополнительной неподвижной маске видимости. Она заменена
проверкой доступности пикселей в физическом кадре камеры.

Доступ ко всему изображению не расширяет проверяемую область. Итоговая маска
остаётся внутри пересечения ROI эталона, подтверждённого контура и дополнительно
уточнённой границы, за вычетом исключающих зон и фиксированного запаса.
Сохраняется прежнее ограниченное плавное уточнение границы: оно может только
сужать маску. Поэтому открывшийся пластик не включается только из-за того,
что убрано ограничение старым ROI текущего кадра.

Защитный запас по-прежнему **1 px исходного кадра по каждой оси**, с прежним
округлением при уменьшенном масштабе. Запас применяется перед пересечением
с доступными пикселями камеры: это не добавляет второй отступ возле края кадра.
ROI-aware предобработка эталона и текущего изображения сохранена.

## Когда пикселей на снимке действительно нет

Если хотя бы часть требуемой области эталона после измеренного переноса
выходит за **физический кадр камеры**, инспекция возвращает `label_out_of_frame`
и `label_tracking.boundary_status = out_of_frame`. Та же диагностика передаётся
в `inspection_exclusions.label_boundary.status`. В интерфейсе появляется
сообщение, что контролируемая часть этикетки вышла за кадр и полная проверка
невозможна. Проверка доступности выполняется до подгонки контура, чтобы
подгонка не могла скрыть отсутствие данных.

Требуется только область ROI эталона внутри этикетки, а не вся этикетка или
ведро вне выбранной зоны. При чувствительности 0% прежнее отключение брака
сохранено. При превышении допустимого сдвига остаётся причина `shift_exceeded`.
При выключенном checkbox компенсации с вырезанием этот путь полностью
обходится: используется обычное позиционирование без контурной обрезки.

Измеритель сдвига, приближённые мм, допуски, чувствительность, ослабление
сравнения и формула score в этой задаче не изменены.

## Проверки

Новый C++-тест `reference_roi_sampling_test` проверяет:

- ROI точно по контуру эталона; переносы вверх, вниз, влево и вправо на 4 px
  при масштабе 100% и 50%: нормальная этикетка даёт score 0, исходная маска
  инспекции сохраняется;
- повреждение соответствующего края, оказавшееся за старым ROI текущего
  кадра: контрольный пиксель остаётся в маске, score ненулевой, тестовый порог
  10% превышен;
- отсутствие расширения за ROI/контур эталона и неизменность кэша;
- посторонний тёмный участок вне более узкого ROI: score 0;
- перенос печати на 3 px при неподвижном силуэте ведра: уточнённая маска
  текущего изображения не выходит за истинный силуэт, score 0;
- потерю требуемых пикселей за камерой: отдельная причина неполной проверки;
- доступный край возле камеры без второго защитного отступа;
- чувствительность 0%: прежнее отсутствие reject.

Этот же тест на прежнем `inspector.cpp` воспроизводит ошибку уже в первом
случае: маска при сдвиге вверх теряет полосу, несмотря на доступные пиксели.
Это контроль регрессии, а не только проверка нового кода на самого себя.

## Практические ограничения

Для обнаружения повреждения оно должно находиться внутри исходного ROI
эталона и контура за вычетом фиксированного 1 px. Новый код не включает
части, которые оператор изначально не выбрал для проверки.

Это исправление выборки, а не безошибочная сегментация этикетки. Точность
контура, освещение, достоверность общего позиционирования и прежний радиус
уточнения ±5 исходных px по-прежнему важны. Блики, широкое повреждение,
слабый контраст и нелинейная деформация при провороте остаются ограничениями.
При ненадёжном уточнении сохраняется прежний контур, а не гарантируется
автоматическое удаление любого пластика. Реальные пары со смещением этикетки,
камеры/PLC, длительный поток и Linux в этой задаче не проверялись.
