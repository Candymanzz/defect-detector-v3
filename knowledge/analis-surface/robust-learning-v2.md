## Изменения и поведение

Алгоритм `learning_matcher.{h,cpp}` перенесён из стенда в `cppAnalisSurface/src/core`;
вычислительная реализация совпадает с ним после замены namespace/include. Нативный `inspectFrame`
выбирает новый matcher по настройке камеры до фильтрации компонент и подсчёта score.
При отсутствии образцов основной путь сравнения не меняется. Выключение нового режима сохраняет
исходный matcher `52aa31ea`; callback адаптера стенда в production не нужен.

| Поле API | Default / диапазон | Назначение |
|---|---|---|
| `learning_robust_enabled` | `true`, bool | Новый matcher; `false` возвращает прежнее сопоставление |
| `learning_shadow_enabled` | `true`, bool | Независимое сопоставление плавной тени |
| `learning_search_radius` | `24`, целое 0…64 | Поиск вокруг сохранённого bbox, в исходных px |

Настройки сохраняются через существующий `/settings/:profile` и доступны в временных JSON overrides
и multipart `/inspect`. Недостающие поля старых профилей получают defaults; сохранённые пороги,
ROI, эталоны и образцы не сбрасываются. Неверные сохраняемые значения отвергаются целиком;
неверные временные overrides игнорируются по существующему контракту. Значения `false` и `0` применяются.

Поиск расширяет контекст вокруг сохранённого прямоугольника. Маска применения — пиксели образца,
отличающиеся от эталона больше чем на 6 уровней после подготовки; фон всего bbox не исключается.
При надёжном сопоставлении эта маска переносится за исходный bbox в пределах отдельного радиуса.
ROI продолжает ограничивать diff. Ищутся только полные положения, без циклического переноса/репликации.

Сопоставление изображения использует `TM_CCOEFF_NORMED`, порог 0.8 и минимальное СКО образца 1 уровень.
При недостоверном поиске остаётся попиксельная проверка исходной позиции. Участки меньше 8 рабочих px
по стороне или вне рабочей области пропускаются с диагностикой.

Для тени сравнивается плавная знаковая разница «образец − эталон» с «текущий кадр − эталон».
Печать может оставаться на месте, пока тень сдвигается. Gaussian sigma = max(1,6*scale),
средняя высокочастотная ошибка образца должна быть <=max(2,0.18*средняя абсолютная разница), пик <=18.
Корреляция тени >=0.8; допустимая амплитуда 0.7…1.3 от образца и смещение яркости ±12 уровней.
Вычитается только найденная плавная компонента, а детали текущего кадра проверяются по эталону
с прежним min/max-конвертом X/Y. При пригодной модели тени она не смешивается с другим переносом изображения.
Фильтрация ограничена локальным контекстом с запасом 4*sigma, а не всем кадром.
Это исходные инженерные ограничения стенда, не калибровка на производственных дефектах.

Хранение привязано к прежним камере/изделию и fingerprint эталона. Формат `learned-regions/cases.json`
и PNG не меняется. На Windows замена существующего JSON сделана через `MoveFileExW`, как в стенде;
Linux сохраняет `filesystem::rename`.

## API, Java и интерфейс

C++ HTTP-ответ и журнал инспекций содержат `learning_engine`, `learning_robust_enabled`,
`learning_diagnostics`, `learning_ms`, исходный score и совпавшие IDs. Диагностика показывает способ,
применённое смещение, сходство, убранные/оставшиеся рабочие пиксели и причины отказа модели тени.
В performance tracing добавлен этап `learning_ms`. Рабочие пиксели зависят от `inspect_scale`.

`CppAnalisSurfaceHttpSupervisor` переносит эти поля в RPC-ответ. Они входят в `InspectionDecision.learning`
того же кадра, затем в `server.inspect_result.learning` и архивный `result.json.learning`.
History API читает их после перезапуска; frontend переносит их в тот же `InspectResultPayload`.
Старые конструкторы решения и архивы без этих полей совместимы; нет глобального кэша «последней диагностики».
Python-путь не переводится на C++ matcher.

В `DetectorSettingsPanel` добавлены два переключателя и радиус; настройки работают и в тестовом окне.
В результате инспекции — раскрываемая панель «Применение образцов нормы».
Основное действие «Дообучить» продолжает автоматически вырезать bbox по ненулевой хитмапе с запасом
10 исходных px. Ручной прямоугольный редактор стенда в основной UI не переносился: задача меняет
применение образцов, сохраняя существующий способ их добавления.

## Решение и компромиссы

Выбран точный перенос проверенного matcher вместо повышения общих допусков X/Y, которое ослабляет
все проверки. Настройки/хранение интегрированы в существующие профили, без профиля стенда или новой БД.
Диагностика проходит с решением кадра, чтобы история не показывала результаты другой инспекции.
Совместимость позволяет сравнивать с прежним matcher переключателем.

Алгоритм не может отличить реальный дефект, визуально повторяющий обученную допустимую тень.
Большие/многочисленные образцы увеличивают вычислительную цену. Произвольное вращение и деформация
не моделируются; тесно вырезанный образец иногда требуется сохранить заново с окружением.
