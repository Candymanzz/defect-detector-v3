# Исправление смешанной кромки при допустимом сдвиге — 2026-11-06

Ветка `compensation`, исходная база `67f90237493df2a96432465a25e354cdf348647d`.
Изменены исходники C++ и регрессионный тест. Установленный runtime, эталоны,
конфигурация и Git-история не изменялись.

**Уточнение пользователя:** чувствительность 0% намеренно отключает весь
surface-reject, включая превышение смещения. Это корректное поведение,
а не баг из предыдущего диагностического отчёта; оно сохранено.

## Что исправлено

При дробном движении крайний пиксель камеры уже содержит смесь этикетки и
неподвижного фона. Предыдущий INTER_NEAREST для переносимой маски принимал
часть таких пикселей за чистую этикетку. Обратный warp сохранял примесь, а
разные веса подготовки эталона и кадра дополнительно меняли край.

В ветке компенсации явно заданного ROI:

1. Из маски строится опора с защитой в один **исходный** пиксель. Она переносится
   линейно; используются только полностью покрытые пиксели. При слишком узком
   ROI без внутренней области сохранён перенос полной маски nearest, чтобы
   сравнение не превратилось в две пустые картинки.
2. Текущая яркость и опора переносятся обратно вместе.
3. Яркость эталона умножается на ту же восстановленную опору. Обе картинки
   уменьшаются, сглаживаются Gaussian5 и делятся на одинаковые веса.
4. Основное сравнение и robust learning получают этот подготовленный эталон.
   Он локален для вызова: общий кэш не перезаписывается.

Маска результата и площадь ROI, формула score, усиление углов, глобальное
ослабление, phase256/ECC512, калибровка и пределы смещения прежние. Без явного
ROI и без применённой компенсации прежние пути сохранены.

Это **компромисс по наблюдаемости самой кромки**: при компенсации исключаются
образцы порядка 1–2 native px у границы, уже смешанные с фоном или ненадёжные
при интерполяции. Выходная маска не уменьшается, но это не означает, что каждый
крайний входной пиксель продолжает влиять на результат. Очень тонкий настоящий
дефект только в этой полоске может стать менее заметен. Широкая полоса в мм
не исключается, глобальная чувствительность не понижается.

## Проверки до/после

Архив `iml-frame-archive`, первые/последние кадры камер 0/1/3/4/5/6/8/9.
Из фотографий построена модель перемещения слоя; это **контрольные переносы
реальных снимков**, а не размеченные реальные пары «эталон/сдвинутое ведро».
ROI ограничен видимой частью с запасом 24 px до границы кадра. Переносы
±0,5/1,25/3,75 расчётных мм, предел 4,5 мм; масштабы 20/50/73/100%.

|---|---|---:|---:|
| Архив | 50% / 3 px | 384 | 3 → 0 |
| Архив | 80% / 3 px | 384 | 102 → 0 |
| Архив | 95% / 3 px | 384 | 140 → 0 |
| Архив | 50% / 0 px | 384 | 24 → 0 |

Независимая модель сначала рисует движение на сетке 4x, затем интегрирует
пиксели. Она не использует маску алгоритма для создания native-края. Всего
432 случая; при чувствительности 50/80% и ослаблении 0/3 px — **0/288 отказов**.
Оценки сдвига для всех 2304 архивных и 432 независимых случаев побитно совпали
с исходной версией. Самосравнения не получили ненулевого score.

Повторены 339 пар «оценённый/точно известный сдвиг», 678 инспекций:

- 96 архивных и 96 независимых пар при 50/80%: обе ветки без ложного брака.
- Ниже допуска на 0,125 мм: 48/48 приняты, прежние 14 отказов по score исчезли.
- Выше допуска на 0,125 мм: 48/48 `shift_exceeded`.
- Ровно на пределе: прежние 18/48 `shift_exceeded` из-за погрешности измерения;
  отказов по score нет. Скрытый запас к допуску не добавлялся.
- При чувствительности 0%: 3/3 превышения приняты, как и требуется.

Повреждения края: 384 случая, глубина 2/4/8/16 native px, длина 30 px,
четыре края, чёрные/белые дефекты, смещения 0/±8,5 px, масштабы 50/100%,
чувствительность 50/80%. Новых потерь ранее обнаруживаемого дефекта с
локальной подсветкой **нет**. Все 192 случая глубиной 8/16 px обнаружены.
Прежние пропуски 2–4 px на 50% сохранились; это не доказательство сохранения
любого возможного однопиксельного повреждения.

Регрессионный `label_roi_test` дополнен независимой моделью, цветным/монохромным
вводом, дробными переносами, краевыми повреждениями, проверкой неизменности
кэша, параллельной компенсацией и отключением reject на 0%. Проверка узкого
ROI защищает от получения двух пустых картинок. Расширенный тест до добавления
проверки узкого ROI был отдельно связан со старым core: он падает на
`mixed boundary falsely rejected scale=0.5 dy=-15.75`, новый core проходит.

Полный Release и итоговые проверки сборки описаны в итоговой записи ниже.
HTTP/SHM: 300/300 успешных проверок самосравнения, 10 workers, 6 масштабов,

## Что остаётся ограничением

- На 95% чувствительности ещё есть отказы: 3/72 в независимой модели при
  ослаблении 3 px и 14/384 в архивной модели при 0 px. Полное отсутствие
  ложного брака во всех настройках не подтверждено.
- ROI должен соответствовать контролируемой этикетке. В отдельной модели
  с неподвижными полосами фона и ROI, расширенным на 4/8 px наружу,
  осталось 14–16/16 отказов на комбинацию. Это реальные изменения включённого
  фона; данное исправление не отделяет его автоматически внутри ROI.
- Выход этикетки из кадра, сложное вращение, перспектива, блики и реальные
  производственные пары не покрыты гарантией. Миллиметры пока приблизительные.
- Строгое сравнение измеренного смещения с пределом и confidence-порог прежние;
  поведение ровно на границе допуска не исправлялось этой задачей.

Альтернативы: одного улучшения ECC недостаточно (подтверждено прежней
проверкой точного сдвига). Глобальное снижение чувствительности, увеличение
ослабления или удаление широкой полосы ROI не применялись, поскольку они
маскируют больше дефектов. Выбран ограниченный по native-пикселям подход с
общими весами эталона и кадра и отдельной проверкой повреждений кромки.

Артефакты: `CppDetector/artifacts/white-strip-fix-20261106` в рабочем тестовом
каталоге `huinya pashi`; `summary.json`, `candidate1`, `focused-results`,
логи сборки/тестов и HTTP. Производственные изображения и артефакты в Git
не добавляются.
