# Оставшиеся проблемы и границы проверки

Срез **2026-10-27 · `cpp-detector` · `bfd9b54a`**. Не считать наличие списка доказательством отсутствия других ошибок. [Контекст](PROJECT_CONTEXT.md).

## 1. Некорректный ответ детектора может стать ACCEPT

**Подтверждено локальным mock HTTP-тестом; код всё ещё содержит причину. Приоритет высокий.**

В [CppAnalisSurfaceHttpSupervisor.inspectResponse](../orchestrator-java/src/main/java/com/example/iml/orchestrator/integration/clientapi/CppAnalisSurfaceHttpSupervisor.java) `ok` вычисляется исключением статусов БРАК/FAIL/ERROR/REJECT. Любой другой статус допускается, включая UNKNOWN.

Воспроизведение: HTTP 200 с пустым телом, `{}` или `{"status":"UNKNOWN"}` → `status=UNKNOWN`, `ok=true`. При геометрии `SKIPPED` [агрегатор](../orchestrator-java/src/main/java/com/example/iml/orchestrator/integration/pipeline/decision/DefaultInspectionDecisionAggregator.java) выдаёт ACCEPT. Явный ERROR и БРАК были контрольными случаями и приводили к REJECT.

Ожидаемое исправление — валидировать положительный вердикт и структуру ответа; отсутствие измерения не приравнивать к подтверждённому ГОДЕН. Обработку штатного отсутствия эталона/режима CAPTURE проверять отдельно. Это **не исправлено** изменением кэша.

## 2. Устаревшая подсказка и резервные значения UI

**Подтверждено кодом.** [DetectorSettingsPanel](../front-end/src/components/SettingList/DetectorSettingsPanel.tsx):

- Подсказка связывает score=100% с 5% площади ROI, хотя C++ использует 0.2% — расхождение в 25 раз.
- `DEFAULT_SETTINGS.threshold=0.25`, серверный default — 0.6. Полная успешная загрузка настроек подставляет серверное значение; не утверждать, что каждый текущий запрос поэтому идёт с 0.25.

Исправлять согласованность UI и контракта, сохраняя действующую серверную шкалу 0.2 и threshold 0.6, если отдельно не согласована смена алгоритма.

## 3. Конкуренция фоновых карт и новых вердиктов

**Код + локальный нагрузочный тест.** C++ ограничивает инспекции общими слотами. Экспорт карты по дополнительному запросу включает вычислительную работу; перенос вызова в Java sidecar не резервирует ресурсы для следующего основного запроса.

В искусственном тесте 10 инспекций + 10 запросов визуализации p99 ожидания слота основного запроса был 103.7 мс, максимум 124.6 мс; время пакета до последнего вердикта — в среднем 184.9 мс против около 83 мс без этих запросов. Это не запись точного расписания sidecar на станке. [Методика](performance/2026-10-27-speed-stability.md).

## 4. Семантика настроек отличается от старого Python

**Подтверждено кодом; поведение, требующее внимания, а не автоматически выбранная новая правка.** В C++ sensitivity=0 не отключает весь детектор, X/Y=0 не отключают позиционирование, а X/Y-допуски сравнения не измеряют допустимое положение этикетки в мм. [Точные формулы](analis-surface/overview.md).
