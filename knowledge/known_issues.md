# Оставшиеся проблемы и границы проверки

Срез **2026-10-28 · `ppc-reserv`**. Перенос из 123 описан в [INSPECTION_PORT.md](../cppAnalisSurface/INSPECTION_PORT.md). Исторические воспроизведения отмечены отдельно. [Контекст](PROJECT_CONTEXT.md).

## 1. Исправлено: некорректный ответ детектора становился ACCEPT

**Исправлено 2026-10-28 и покрыто CppAnalisSurfaceMetricContractTest.** Неизвестный статус, отсутствующие
числовые score/threshold и нечисловые/нефинитные значения дают MSG_ERROR с ok=false. Штатные no_reference/CAPTURE
ветки обрабатываются отдельно и не менялись. Далее — историческое воспроизведение до исправления.

До исправления в CppAnalisSurfaceHttpSupervisor.inspectResponse `ok` вычислялся исключением статусов
БРАК/FAIL/ERROR/REJECT, допуская UNKNOWN. Теперь принимаются только известные статусы и корректная структура измерения.

Воспроизведение: HTTP 200 с пустым телом, `{}` или `{"status":"UNKNOWN"}` → `status=UNKNOWN`, `ok=true`. При геометрии `SKIPPED` [агрегатор](../orchestrator-java/src/main/java/com/example/iml/orchestrator/integration/pipeline/decision/DefaultInspectionDecisionAggregator.java) выдаёт ACCEPT. Явный ERROR и БРАК были контрольными случаями и приводили к REJECT.

Исправление относится к проверке контракта Java-клиента, отдельно от исправления кеша.

## 2. Исправлено: устаревшая подсказка и резервные значения UI

**Исправлено 2026-10-28.** Подсказка теперь соответствует 0.2% ROI, резервный threshold=0.6.
Далее — исторические несоответствия DetectorSettingsPanel:

- Подсказка связывает score=100% с 5% площади ROI, хотя C++ использует 0.2% — расхождение в 25 раз.
- `DEFAULT_SETTINGS.threshold=0.25`, серверный default — 0.6. Полная успешная загрузка настроек подставляет серверное значение; не утверждать, что каждый текущий запрос поэтому идёт с 0.25.

Исправлять согласованность UI и контракта, сохраняя действующую серверную шкалу 0.2 и threshold 0.6, если отдельно не согласована смена алгоритма.

## 3. Конкуренция фоновых карт и новых вердиктов

**Код + локальный нагрузочный тест.** C++ ограничивает инспекции общими слотами. Экспорт карты по дополнительному запросу включает вычислительную работу; перенос вызова в Java sidecar не резервирует ресурсы для следующего основного запроса.

В искусственном тесте 10 инспекций + 10 запросов визуализации p99 ожидания слота основного запроса был 103.7 мс, максимум 124.6 мс; время пакета до последнего вердикта — в среднем 184.9 мс против около 83 мс без этих запросов. Это не запись точного расписания sidecar на станке. [Методика](performance/2026-10-27-speed-stability.md).

## 4. Семантика настроек отличается от старого Python

В C++ sensitivity=0 не отключает весь детектор. Основные допуски смещения теперь в мм; прямые старые px-overrides
сохраняют прежний минимальный запас позиционирования. Это не полная геометрическая проверка положения этикетки
относительно ведра. [Точные формулы](analis-surface/overview.md).

## 5. Требуют проверки: масштабы мм и слабоконтрастный стык

Масштабы камер пока приблизительные. При сильном уменьшении (например 0.2) оценка переноса около границы допуска
может давать заметную погрешность; цифровое масштабирование не заменяет проверку на машине.
Настраиваемый min_contrast стыка применяется к краям во втором проходе; первый ridge-поиск пока имеет фиксированный
порог 6. Слабая линия поэтому может не находиться даже после снижения min_contrast. Этот алгоритмический предел
не исправлялся переносом, как и в 123.

- Ложный брак и пропуски на размеченных кадрах. У `frames36` нет подтверждённой разметки дефектов; стабильность ответа не равна качеству классификации.
