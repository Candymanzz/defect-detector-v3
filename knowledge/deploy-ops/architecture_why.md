# deploy & ops — architecture "WHY"

Back to [overview](./overview.md) · Evidence tags: **[doc]** **[code]** `⚠️ [GUESS/CONJECTURE]`.

1. **Build ≠ run ≠ measure** (`rebuild-and-run.sh` builds only; `run-supervised.sh`/`run-rt.sh` run; `-r` observes). **[doc]** `RUN.md`, `RT-LINUX.md`: “Скрипт только собирает… Он не останавливает и не запускает сервисы”; diagnostics “только наблюдает: не запускает и не останавливает сервисы, не меняет affinity”. Commits `80c92a89` (“убрал перезапуск в ребилд анд ран”), `e1c537b3`, `0af3683a`, `7201861d`, `4c0c0ebc` (2026‑10‑14). Reason: measuring RT jitter requires an unperturbed system; restart side effects during a rebuild once stopped a running line ⚠️ [GUESS/CONJECTURE].
2. **Atomic replace of `camera_worker` binary** (`cp` to `.new.$$` then `mv -f`): Linux refuses to overwrite a running executable (comment in script).
3. **Separate CMake build dir `build-linux`** vs Windows cache **[doc]** comment; the orchestrator keeps looking at `camera-worker/build/camera_worker`.
4. **Affinity applied to the supervisor** (`taskset … run-supervised.sh`): every child inherits it, including future restarts by the watchdog; third-party processes are not touched **[doc]** `RT-LINUX.md`. Verified before launching with a throw-away `taskset … python3` (fail early, before stopping the old stack).
5. **Historical default: four app cores within a six-core host [doc]**: `2-5,8-11` represents four physical cores plus SMT siblings on the recorded topology, with the remaining two for housekeeping. The orchestrator, camera/geometry workers and Python processes inherit this mask when launched through `run-rt.sh`. `0da1c38e` sets `python_server_pool_size 6`; six processes do not prove six reserved cores. **[owner: 2026-10-20]** Current machine context is six cores with RT; actual allocation and scheduling policy need host verification, so this historical split must not be presented as the measured current state. See [production environment](./production_environment.md). The recorded isolation profile uses `nohz_full`, `rcu_nocbs`, IRQs steered to `0,1,6,7` and `isolcpus` without `domain` so balancing among app CPUs remains enabled **[doc]**.
6. **Stop script is /proc-based, repo-root scoped** (`stack_processes.is_service`): it only kills processes whose cwd/args live under the repo root, re-scans after SIGTERM because EXIT traps of launchers may spawn cleanup children, and refuses to claim success if any survivor remains **[code]** `stop_stack.py:157-186`.
7. **Kiosk separation**: the installed Electron UI belongs to the `kiosk` user/session and survives backend restarts (`--skip-kiosk`, `.kiosk-paused.json`); the developer's Vite/Electron autostart is disabled when a kiosk is installed (`run-supervised.sh`). Rationale: operators keep a UI while engineers redeploy the backend ⚠️ [GUESS/CONJECTURE].
8. **Passwordless frontend deploy through a fixed helper** (`4616cb7a`, `setup-frontend-updates.sh`): sudoers only for `/usr/local/sbin/defect-detector-restart-ui` (no args), writable dirs limited to `dist/ electron/ package.json`; `node_modules` and `chrome-sandbox` keep their runtime ownership/permissions, the app root belongs to `root` **[doc]** `RUN.md` (⚠️ [GUESS/CONJECTURE]: Chromium's setuid sandbox helper must not be writable by the deploy user).
9. **System profile export/import instead of golden disk image** (`system-profile.py`): clones services, kiosk, GRUB RT parameters and governor between identical PCs, explicitly excluding identities and secrets (`shadow, machine-id, SSH keys, Tailscale state`) and refusing to proceed when different isolation already exists **[doc]** `deploy/linux/README.md`.
10. **Tailscale + SSH + VNC** remote access (`deploy/remote-access`) for support without a VPN appliance; every person needs an individual Tailscale access **[doc]**.
11. **Session log directory shared through `IML_LOG_SESSION_DIR`**: one folder per launch correlates Java, Python, C and frontend logs; created by the Linux supervisor (`run-supervised.sh`) or by the JVM on direct start (`SessionLogs.initialize`) **[doc]** `LOGGING.md`; added in the “мега логирование” commits `4c0c0ebc`, `8f03d0cd`, `a57269cc` (2026‑10‑14).
12. **Config templates as `config.exemple/` with the real `config/` ignored**: machine-specific IPs, ports and serials must not leak between PCs; consequence: a fresh checkout cannot start without manual config (audit item #1).
13. **PLC map as YAML next to CSV exports** (`plk/`): lets electricians change an address without Java changes (“Как поменять сигнал по FINS без правки кода”) while CSV remains the source-of-truth export from CX-Programmer **[doc]** `plk/README.md`.
