# Выключение вспышек по ExposureEnd — 2026-11-05

## Задача и решение

Владелец потребовал принимать от камеры `ExposureEnd` и выключать вспышки
при его приходе, если событие приходит регулярно. Исходный checkout:
`boobs+pasha / fd442c97`; код и рабочие настройки на этой машине изменены
локально, без pull/push и нового коммита. Прежние локальные заметки сохранены.

Свет включается по DI2↑. Для раннего выключения теперь требуется завершение
экспозиции **всех камер с открытыми workers** (на стенде 0–9): один источник
света может освещать несколько камер, а времена экспозиции могут различаться.
Не используем окончание только камеры 0 для выключения общего банка.

Условие регулярности реализовано проверкой **30 последовательных полных окон
DI2**: у каждой камеры должен прийти ExposureStart, затем ExposureEnd с большей
аппаратной меткой в том же окне. Проверка завершается на DI2↓, раннее
выключение разрешается со следующего окна. Это конечная эксплуатационная
проверка, а не гарантия доставки всех будущих событий.

При недостающем событии, новом сообщении о потерях очереди или нарушении
порядка подтверждение сбрасывается и снова нужна серия полных окон.
Если все окончания не получены, сохраняется прежнее выключение по DI2↓.
Повторы одного события не дают повторного раннего Off. Уведомления,
сформированные до нового DI2↑, не могут погасить свет следующего окна.
Поведение постоянного режима света не меняется.

## Реализация

- Нативные подписки Line0RisingEdge, ExposureStart, ExposureEnd через уже
  открытые handles MVS. Для JNI включены все камеры; отдельный worker по
  умолчанию по-прежнему пишет диагностику камеры 0.
- `IML_CAMERA_EVENT_CAMERA=-2` явно выбирает все камеры, `-1` отключает,
  `N` оставляет одну. При выборе одной камеры общий gate не сможет пройти
  проверку остальных и сохранит DI2↓ fallback.
- SDK callback только копирует запись в ограниченную неблокирующую очередь.
  Существующий dispatcher вызывает Java через JNI перед записью JSONL;
  этот вызов передаёт идентификатор камеры, тип события, аппаратные ticks,
  CLOCK_MONOTONIC при получении callback и счётчик потерь.
- NativeCameraEvents передаёт события подписанному IntervalFlashController.
  ExposureEndFlashGate сопоставляет события внутри каждого DI2-окна.
  Вызовы банка света выполняются на отдельном последовательном executor:
  SDK callback и поток приёма кадров не ждут команды выключения.
- При close подписка снимается; отложенный ранний Off проверяет поколение
  окна и не применяется к следующему. Старые сообщения/потери не скрываются.
- Журналы камеры: `config/logs/camera-events-cam-N.jsonl`.
  Runtime: `exposure_end_validation`, `exposure_end_complete`,
  `bank_off_complete` с длительностью вызова банка.

В шаблоне и рабочем `config/blocks/52-io.yaml` добавлены:

```yaml
light_servers:
  interval_flash:
    off_on_exposure_end: true
    exposure_end_validation_cycles: 30
```

При отсутствии ключа `off_on_exposure_end` код сохраняет DI-only режим.
Для отката поведения достаточно false и перезапуска backend; обработка
кадров, алгоритм детектора, Timer5/DO5 и параметры экспозиции не менялись.

## Ограничения

Уведомления приходят по сети с задержкой; dispatcher проверяет очередь раз
в 10 мс, затем отдельный executor отправляет команду банку. Это программное
выключение после получения ExposureEnd, а не аппаратная синхронизация вспышки
с выдержкой. Фотодиодом конец света не измерялся.

Автоматический допуск относится к DI2-окнам и предполагает один аппаратный
цикл съёмки в окне, как текущий capture pipeline. Он не заменяет контроль
снимков/вердиктов и не проверяет здоровье всех сервисов. При перезапуске
счётчик 30 циклов начинается заново. При неподдерживаемом событии/платформе
раннее выключение не получит допуска. Текущий native event-путь — Linux MVS.
