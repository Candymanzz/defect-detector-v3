# Подготовлены параметры камер против зернистости — 2026-11-03

Пользователь разрешил применить настройки и сообщил, что перезапустит приложение
сам. Уточнено, что цель — настройки самих камер для улучшения инспекции, без
вмешательства в алгоритм анализа. Первоначальная интерпретация агента про
фильтрацию превью была неверной: все её незавершённые правки сняты до сборки.
Изменений production Java/C++/frontend по этой задаче не осталось.

Перед записью камера0 уже имела в camera_runtime_settings.json 100 мкс и
11.991 dB (фактическое квантованное значение около12). Камеры1–9 оставались
на50 мкс/18 dB. Камера0 сохранена как есть, у1–9 изменены только exposure_us=100
и gain_db=12.0 в `config/data/camera_runtime_settings.json`.

Причина выбора: пробная пара из предыдущей диагностики, уже выставленная
для камеры0. При непрерывном свете удвоение выдержки и уменьшение усиления
примерно на6 dB ориентировочно сохраняют яркость, собирая больше фотонов.
Это не подтверждённый оптимум: реальная длительность вспышки и смаз на движении
не измерены. По обработке архивного JPEG нельзя валидировать новые параметры
съёмки. [Предшествующая диагностика](2026-11-03-edge-blur.md).

До записи сохранена резервная копия в
`.verification/camera-noise-settings-20261103/camera_runtime_settings.before-*.json`.
Запись атомарная, исходные байты перепроверены перед заменой. Проверено, что
все остальные поля каждой камеры, включая ROI, gamma, WB, black_level,
триггер и таймаут, сохранены; все10 камер имеют100 мкс/около12 dB.

API записи/захвата не вызывали, службы/приложение не перезапускали.
Параметры подготовлены на диске и применятся native при следующем запуске
из сохранённого camera_runtime_settings.json. Если до перезапуска оператор
сохранит настройки из старой сессии, приложение может перезаписать файл.
После запуска нужны проверка GET реальных значений и сравнение снимков/смаза;
они ещё не выполнены. Пересборка не нужна: изменился только рабочий файл настроек.
