# 404 при сохранении дообучения — 2026-11-03

Ветка `boobs+pasha`, исходный HEAD `623f2f5a`. Пользователь сообщил, что кнопка «Дообучить»
показывает «детектор не поддерживает сохранение фрагмента».

## Подтверждённая причина

Frontend уже обновлён и перезапущен в 11:02, а backend `defect-detector.service` работал
с 10:03:46. Java PID 2178 и C++ PID 2323 были запущены до переноса дообучения.
Прямой GET `http://127.0.0.1:8000/learning/accepted-cases` и GET через
`http://127.0.0.1:8099/api/client/learning/accepted-cases` возвращали 404.
Старый C++ процесс не имел нового маршрута; ошибка UI соответствовала этому ответу.

Сборки на диске были уже обновлены: C++ от 11:01:50, JAR от 11:00:21.
SHA256 `cppAnalisSurface/build/cpp_analis_surface` совпал с изолированной сборкой,
прошедшей CTest/HTTP-проверки при переносе. JAR содержит `LearningDiagnostics`.
Повторная сборка или изменение алгоритма для исправления 404 не требовались.

## Исправление и проверка

Перезапущен только backend командой `pkexec /usr/bin/systemctl restart defect-detector.service`.
Сервис active с 11:16:02, Java PID 29119, C++ PID 29162;
новый detector_id `cpp-analis-surface-5d98fce87c83` вместо `cpp-analis-surface-92751d9c77d0`.

- Прямой и проксированный GET образцов: HTTP 200, загружен 101 существующий образец.
- POST `/api/client/learning/regions?productType=route-check&cameraId=0` с пустым телом:
  HTTP 400 `product_type and file required`, то есть маршрут сохранения доступен
  через тот же Java proxy, которым пользуется UI. Пробные образцы не добавлялись.
- API настроек камеры 0 возвращает миллиметры, сохранённые 8.6/8.3 мм и новые настройки
  дообучения (robust=true, shadows=true, radius=24).
- Установленный JS `/opt/defect-detector-ui/dist/assets/index-XGLdN_LC.js` совпадает
  с локальным по SHA256; содержит оба метрических поля и `inspect_scale step=.01, factor=100`:
  шаг интерфейса остаётся 1%.
- Камеры 0–9 запустились по журналу. Первый цикл после старта выдал `capture_window_closed`;
  это не проверка успешного захвата или физической отбраковки. Полный цикл станка не подтверждён.

Сохранённые настройки/эталоны/образцы не редактировались, UI повторно не устанавливался.
Фактическое добавление нового образца оператором после исправления ещё не проверено.

## Вывод для обновления

`rebuild-and-run.sh` только собирает backend и устанавливает UI; он явно не перезапускает
backend. Перезапуск только kiosk оставляет старую C++/Java механику в памяти.
После обновления, требующего новых backend API, сверять PID/время запуска, detector_id,
доступность маршрута напрямую и через Java. Эту причину нельзя считать устранённой одной сборкой.
