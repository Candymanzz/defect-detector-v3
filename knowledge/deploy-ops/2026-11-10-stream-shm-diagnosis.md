# femboy36: отсутствуют стримы после Ansible deploy — 2026-11-10

## Подготовлено исправление

Через D-Bus подтверждено фактическое RemoveIPC=true, через systemctl —
CanReload=yes для systemd-logind. Sudo без пароля недоступен; pkexec сообщает
No authentication agent found. Применение агентом не выполнено.

Добавлен deploy/ansible/fix-ipc.yml: persistent drop-in RemoveIPC=no,
reload logind, проверка b false через D-Bus, restart только backend,
ожидание HTTP и проверка SHM всех настроенных камер от пользователя o.
Тот же IPC-предохранитель подключён к обычному deploy до остановки;
SHM проверяется при запуске и откате. RemoveIPC=no — политика всего ПК;
она не ограничена одной службой. Системный пользователь рассматривался как
альтернатива, но потребовал бы миграции установки и прав.

После локальной проверки владельцу нужно запустить fix-ipc.yml с
--ask-become-pass в обычном терминале. Далее проверить stream и сохранность
SHM после logout. До получения результата нельзя считать проблему исправленной
на станке. Локальный тест воспроизводит случай open fd + unlink: данные ещё
читаются из открытого дескриптора, но SHM-проверка обнаруживает отсутствие имени.

Владелец сообщил successful deploy (ok62/failed0/rescued0), но отсутствие
стримов. Через обычный SSH из среды агента No route to host; чтение через
`ssh -o 'ProxyCommand=tailscale nc %h %p' femboy36` успешно.

Подтверждено чтением сервера:

- deployed-version.txt: pipeline22, commit32b5965622584f826eaf9f1f2e9303b7e89c0b45;
- defect-detector.service active с 11:35:07+03, NRestarts0;
- JVM оркестратора PID19027, C++19069, supervisor18945;
- /api/cameras возвращает10 ID. В логе camera0 capture_ok с ростом frame_id,
  одновременно client_stream: shm not readable /iml_cam_0_frame;
- /dev/shm пуст. Все10 iml_cam_*_frame открыты JVM и отображены в maps
  с пометкой deleted. Семафоры MVS также отображены как deleted.

Следствие: процессы работают, но именованные SHM-буферы недоступны Java/C++.
HTTP health/наличие Electron этой неисправности не выявляют. Аппаратная
инспекция этим состоянием не подтверждается, не только видеопоток.

Наиболее вероятное объяснение — systemd-logind RemoveIPC: явного override
нет, в конфиге default #RemoveIPC=yes, у o Linger=no. Сессия231 завершилась
11:36:53, первые ошибки стрима11:37:24. Это корреляция и известный механизм,
но инициатор unlink непосредственно не прослежен. Возможность удаления
другим процессом не исключена. Источник поведения:
https://www.freedesktop.org/software/systemd/man/latest/logind.conf.html .

Системные настройки и приложение агентом не менялись, restart не выполнялся;
sudo -n требует пароль. Исправление требует сохранения IPC для службы,
пересоздания буферов перезапуском в согласованное время и проверки, что
буферы и стрим сохраняются после завершения SSH-сессии. Одного рестарта
недостаточно, если причина очистки остаётся. Далее следует усилить проверку
после deployment: наличие всех ожидаемых SHM и реальный кадр, а не только HTTP.
