## Решение и причины

- CMake сохраняет `exclusion_test`, `shift_accuracy_test` и `preprocessing_test`;
  новый объединённый exclusion_test также линкуется с `opencv_video`.
- `Reference::build` использует входящие `inspectionWorkSize` и
  `prepareInspectionGray`, но принимает `exclusions` и вычитает их из масок.
- `Prepared` остаётся неизменяемым для вызывающей инспекции. Native
  `AlignmentPrepared` получает свой список `exclusions`; общая ссылка кэша
  переиспользуется только при совпадении списка. Уже выполняющаяся инспекция
  сохраняет собственный shared_ptr, поэтому другой черновик маски не меняет её.
- На native-resolution coarse phase Hann-маска вырезает зоны до DFT-padding;
  ECC fineMask наследует ROI без исключённых участков. Один вариант маски
  может разделять native alignment между разными inspect_scale. Два различных
  варианта не смешиваются. Положение продолжает измеряться независимо от
  масштаба дефектного сравнения, как во входящей реализации.
- Верхние углы строятся по исходной геометрии ROI до вычитания дыр.
- В восьми Markdown-конфликтах сохранены обе части каждого conflict hunk;
  текущая запись явно отделена от прежних дат/проверок. Инструкция фронтендеру
  дополнена уточнениями о совместимости API и жизненном цикле зон.

Почему нельзя выбрать одну сторону целиком: локальная сторона потеряла бы
новую предобработку/позиционирование, входящая — независимые маски исключения.
Автоматическое объединение inspector.cpp уже использовало обе новые сигнатуры,
но Reference и его native кэш требовали явного согласования.
