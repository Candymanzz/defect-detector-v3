# front-end (`front-end/`)

Back to [global_architecture.md](../global_architecture.md) · [API](./api_contracts.md) · [Why](./architecture_why.md) · `F:` = `front-end/`

## 1. Purpose
Operator/engineer UI shown on the line PC as a full-screen **Electron kiosk** (installed to `/opt/defect-detector-ui`, started by `deploy/kiosk/session.sh`). Functions: 10-camera overview with per-line pass/fail counters and inspection history; per-camera inspection start/stop; reference setup (capture frames of one bucket (5 cameras), draw ROI contour, seam ROI (oriented rectangle) on the joint camera, perspective line, FP zones; send `client.reference_bundle`); heat-map/geometry viewers; archive viewer; analysis/geometry/light/camera settings (TEST mode); PLC panel (signals, timeouts, steel/plastic handle `D4405`).

## 2. Stack
React 19 + TypeScript (strict, `tsc --noEmit` in build) · Vite renderer (`npm run dev` → `scripts/dev.mjs`: picks free port from 5173, starts Vite then Electron with `ELECTRON_RENDERER_URL`) · Electron main/preload `*.cjs` · Vitest · ESLint 10/Prettier. Node ≥20.19. Env `VITE_API_BASE_URL` (default `http://127.0.0.1:8099`), `VITE_WS_URL` (default `ws://127.0.0.1:8765/`) in `F:.env`; in dev the REST base becomes the page origin (Vite proxy: `appEnv.apiRequestBaseUrl`).
~16.3 kLOC TS/TSX (non-test). No state library: module-level stores + hooks (`useSyncExternalStore`).

## 4. Key flows

Reference-frame refresh: **«Новый эталон с прежним ROI»**, implemented in `43ec2a9a`, is available for an active group with a stored reference. It captures new frames, retains existing geometry and auto-submits; confirmation waits for server ACK. The separate **«Новый эталон с новым контуром»** starts the contour workflow. [Details and local-test limits](../recent_context.md#3-replace-reference-frames-while-keeping-roi). A Python restart cannot update this UI; rebuild/install and restart the kiosk frontend.

- **Boot**: `orchestratorWs.connect()` → `server.hello{session_state}`; `GET /api/client/inspection/status`, `GET /api/cameras`; reference images are restored from IndexedDB; counters reset by `inspectionResetVersion`.
- **Reference**: preview frames over WS (`server.preview_batch` while the line is idle/`preview_images_enable`), engineer draws ROI/joint/perspective/FP on each of 5 views, `createReferenceBundleFromCameraFrames` → `orchestratorWs.sendReferenceBundle` → wait `server.reference_bundle_ack` (message_id correlation) → commit images/contours to the library, `disableReferencePreviewImages` (stop heavy previews) → `server.state OPERATIONAL`.
- **Run**: results arrive as `server.inspect_result` per camera (+ `server.inspect_bucket_result` per line). UI shows card images from `/api/inspection-artifacts/{bundle}/…` (immutable) and heat-map by artifact id. Out-of-order protection via frame-id comparison and per-camera enable timestamps (`inspectionAcceptedAfterMsByCameraIdRef`, `…FromFrameId…`).
- **TEST mode**: opening analysis settings switches the server to TEST (DI3 inspections stop; PLC ready drops) → pin an archive frame (`test-pin`) → `test-analyze` with ephemeral knobs → result with `test_analyze_job_id` → on save, knobs are persisted via `/api/orchestrator/analysis-settings/camera/{id}/…`.
- **PLC panel**: lists signals/timeouts; writes only when no reference/inspection (server returns 409 otherwise).
