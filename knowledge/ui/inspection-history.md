## Карточка камеры

В общем результате группы камер [InspectionHistoryModal](../../front-end/src/components/InspectionHistoryModal/InspectionHistoryModal.tsx)
показывает две фотографии для каждой камеры:

1. **Эталон** — изображение из `getReferenceImage(camera_id)`.
2. **Кадр инспекции с тепловой картой** — фактический кадр из результата именно этой камеры
   и выбранной инспекции, поверх которого отображается её heatmap.

Если heatmap ещё не получена или отсутствует, во второй позиции показывается фактический
кадр с подписью «Кадр инспекции». Отсутствующий кадр не заменяется эталоном;
отсутствующий эталон не заменяется фактическим кадром. Это исключает ошибочную подпись изображения.

До исправления обе позиции использовали `referenceImageUrl ?? imageUrl`.
При доступном эталоне вторая фотография повторяла его, поэтому пользователь
не видел фактическое изделие под тепловой картой. При отсутствии heatmap
вместо фотографии отображался только текст о её отсутствии.

## Источники

Фактический кадр выбирается из `InspectResultPayload`:

- Архивный `http_path` / `current.http_path` имеет приоритет; URL версионируется `frame_id`.
- При наличии `artifact_bundle_id` используется
  `/api/inspection-artifacts/{bundle}/frame.jpg` этого результата.
- Иначе используется `http_path` / `current.http_path`, если он передан в результате.
  Отдельный запрос текущего предпросмотра камеры не добавляется.

Существующий выбор heatmap из архива/набора артефактов сохранён.
Смена выбранной инспекции передаёт в карточки её собственные результаты и URL.
Источник эталона — текущая локальная библиотека эталонов; историческая версия эталона
в результате не сохраняется этой правкой.

Наложение выполняет существующий [HeatmapViewer](../../front-end/src/components/HeatmapViewer/HeatmapViewer.tsx).
Нового преобразования координат/обратного позиционирования эта правка не добавляет.
Если сервер отдаёт только изменяемый URL кадра без архивного файла или набора артефактов,
frontend сам по себе не обеспечивает неизменность содержимого такого URL.
